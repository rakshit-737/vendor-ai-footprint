# deck/: the Team Osprey walkthrough deck

`build_deck.py` writes the 13-slide walkthrough plus its appendix as a local `.pptx`, using python-pptx. Every
diagram, table and chart is built from native PowerPoint shapes (autoshapes, glued connectors, freeforms and
tables), so everything stays editable in PowerPoint. The package contains no pictures.

> **Confidential.** The deck stays on this machine and in the private repo. Never upload, publish or share it
> anywhere: no Artifact, Docs, Drive, Slides import or paste site. The build makes no network calls.

## Build

```sh
uv sync --extra deck                       # python-pptx
uv run python deck/build_deck.py --findings runs/findings.json \
    --out submission/Team_Osprey_Vendor_AI_Footprint.pptx
```

`--findings` is optional. It accepts any of these:

- an `AssessmentResult` JSON, as written by `footprint.pipeline.run_assessment` to `runs/<run_id>/assessment.json`;
- the run folder itself (`runs/<run_id>/`);
- a JSON list of `VendorFindings`;
- the smaller deck summary format (`DeckData` in `build_deck.py`).

Without `--findings`, slides 2 and 11 show clearly marked placeholders. Slide 2 keeps the live criticality column,
and slide 11 walks through the fictional V-000 calibration.

| Option | Default | Purpose |
|---|---|---|
| `--out` | `submission/Team_Osprey_Vendor_AI_Footprint.pptx` | output path; must end in `.pptx` |
| `--workbook` | `data/input/Meridian_Vendor_Input.xlsx` | profiles for the live tier table (slides 2, 9, 10) |
| `--config-dir` | `config/` | `rubric.toml`, `depth.toml`, `tou.toml`, and `sources.toml` when present |
| `--seeds-dir` | `seeds/` | aliases used for short vendor names (for example TCH) |
| `--team` | `FOOTPRINT_TEAM_NAME`, else `Team Osprey` | team name on the title, footer and properties |
| `--as-of` | the run's `as_of`, else today | date on the title slide and in the limits column |
| `--chain-vendor` | strongest Confirmed vendor | vendor walked through on slide 11 (for example `V-005`) |
| `--no-appendix` | off | build the 13 main slides only |

The same inputs always give byte-identical output: timestamps are pinned to `as_of`, and so are the zip entries.

## Slides

| # | Slide | Data |
|---|---|---|
| 1 | Title: "Reading the public footprint" | team name, as-of month |
| 2 | Answer first: tier, usage, risk, flip condition, next action | findings (placeholder without them), live tiers |
| 3 | Approach: roles 01–05 mapped to C1–C10 and the two human checkpoints; "AI proposes, code verifies, analyst approves" | static |
| 4 | Outcome 01: functional design, C1–C10 with HC1 and HC2, the stop-rule loop and the release order (its gate is code: the LLM audit) | `diagrams.functional_flow` |
| 5 | Outcome 02: architecture, from interfaces down to outputs, external services and the trust boundary | `diagrams.architecture` |
| 6 | Outcome 03: sources, families by tier with reasons, SR ladder, terms register, exclusions | `depth.toml`, `tou.toml`, `sources.toml` |
| 7 | Outcome 03: evidentiary weight, tag card, four tests, label order, trap vs strong | findings when present |
| 8 | AI layer: roles, payload guard, V1–V9, Gemini vs rules | manifest counts when present |
| 9 | Outcome 04: criticality, formula, floors, and a tier table computed live | `footprint.criticality` on the workbook |
| 10 | Outcome 04: depth ladder, stop rules, modifiers, manual channels, reserved steps | `depth.toml`, `tou.toml`, live tiers |
| 11 | Findings and risk: excerpt → tags → verdict → ARP → flip; fourth-party concentration | findings |
| 12 | Outcome 05: live demo script (3:00), generated by `demo_steps` | findings (excerpt, screenshot, trap and Gemini only when the run has them), live tiers |
| 13 | Recommendations, controls and OSINT limits; every vendor's 30-day action, grouped by its column U playbook (`thirty_day_actions`) | findings when present |
| A | Appendix: rubric anchors, tag legend, verdict rules, risk anchors, workbook fidelity, one slide per vendor | config and findings |

Every slide has speaker notes with its time slot. The main slides add up to about 13:15. The notes cite an Evidence
Log ID for every claim about a vendor.

The human checkpoints are HC1 (tier) and HC2 (evidence; the app's Approve action accepts a vendor's remaining cited
excerpts as part of it), as in the project README. There is no release sign-off: the export is gated by code (the
LLM audit and the integrity check). Rebuild the deck from the final frozen run and rehearse slide 12 in the app
before presenting.

## Style

- Team styling: deep-water ink `0C2D36` and teal `0E7C7B`, with saffron `F2B705` reserved for human checkpoints.
  The deck carries no sponsor branding, logo or name.
- 16:9 (13.33 × 7.5 in), Calibri throughout (Consolas for tag strings), and no text smaller than 10 pt.
- Each outcome slide has an "Outcome 0X" corner tag.

## Files

- `build_deck.py`: findings input (`load_findings`, `summarize_assessment`), live inputs, the slide builders,
  `build_deck(...)` and the CLI `main(...)`.
- `diagrams.py`: palette `C`; primitives (`box`, `label`, `pill`, `badge`, `connect`, `arrow`, `polyline`,
  `write_text`); diagrams `functional_flow` and `architecture`.
- Tests: `tests/unit/test_deck.py`, offline, with sockets blocked.
